# Дата: 2026-03-28

- **Что было сделано:**

Сегодня я реализовал новую фичу для нашей Edge Function. Ментор Ольга показала мне инструкцию, написанную клауд кодом, где подробно объяснялось, как это можно реализовать, и я принялся за дело.

Раньще наша Edge Function делала только один запрос к LLM и получала стрим, в котором нужно было аккуратно отделить фидбек от JSONa c данными по ответу. Конструкция была хрупкой и сложночитаемой, хоть и работала. Поэтому ментор Ольга предложила использовать function calling, который доступен для Грока, и делать два запроса: один с фидбеком в стриме, а второй с функцией, которая будет распределять баллы по рубрикам.

В итоге у нас появилось три системных промпта вместо одного — один общий, с основными правилами и указаниями, и два других с дополнительными правилами для двух отдельных запросов, которые добавлялись к общим.

В результате код намного сократился, поскольку теперь уже не нужно выковыривать из стрима JSON. Но появились и некоторые сложности, про которые я напишу ниже.

- **Проблемы, с которыми я столкнулся:**

Проблема была в том, что теперь LLM начала щедро раздавать баллы даже за те рубрики, по которым студент ничего не ответил. И ответ, за который он раньше справедливо получал 38 баллов, теперь оценивался в 63.

Как оказалось, с functional call LLM работает немного иначе. Если раньше был один запрос, и LLM сразу решала, за что и сколько поставить баллов, то теперь часть работы перешла на функцию. И LLM, как я понял, на всякий случай стала более вежливой, поэтому пришлось добавить более строгие инструкции, чтобы оценка была справедливой.
