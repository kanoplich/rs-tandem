# Дневник разработки: RAG Chat Assistant

## Какая задача была сделана

Реализация AI-чата, как помощника для подготовки к собеседованиям на платформе rs-tandem. Так как база данных по вопросам сложная, и на практике оказалось, что для того, чтобы пройти на максимальный бал необходимо обладать широким спектром знаний middle+ уровня, и их можно получить только из базы данных. Поэтому было принято решение разработать чат-помошник, который поможет разобраться в задании, направит к правильному ответу, но не выдаёт его напрямую. Основан на RAG (Retrieval-Augmented Generation) — поиск релевантных задач через векторные embeddings из базы tasks c golden_answer + генерация ответа через LLM.

## Архитектура

```
Вопрос пользователя → Edge Function
  → OpenAI embedding (векторизация вопроса)
  → pgvector (поиск похожих задач по всей базе)
  → Groq LLM (генерация ответа с golden_answer как скрытый контекст)
  → Стриминг текста → Клиент
```

Ключевой принцип безопасности: `golden_answer` используется внутри edge function как контекст для LLM, но никогда не передаётся на клиент.

## Процесс разработки

### Фаза 1: Планирование

Перед началом разработки был составлен детальный план реализации (`docs/rag-chat-implementation.md`), с помощью модели Claude Code Opus 4.6
План включал:

- Схему потока данных
- Объяснение принципа работы векторного поиска vs обычного текстового
- Роль каждого компонента Supabase в проекте
- Пошаговый план из 5 фаз
- Модели безопасности и оценку стоимости

На этапе планирования была проведена аналитика по pgvector — сравнение индексов HNSW и IVFFlat. Рекомендация Supabase — использовать **HNSW**: можно создать на пустой таблице, не требует перестроения при изменении данных.

### Фаза 2: Миграция базы данных

**Файл:** `supabase/migrations/20260329000000_add_vector_embeddings.sql`

Что сделано:

- Подключено расширение pgvector
- Добавлена колонка `embedding vector(1536)` в таблицу `tasks`
- Создан HNSW-индекс для cosine similarity search
- Создана SQL-функция `match_tasks()` для поиска релевантных задач

Миграция применена к локальной базе без проблем.

### Фаза 3: Генерация embeddings

**Файл:** `supabase/functions/generate-embeddings/index.ts`

Edge function для одноразового заполнения колонки `embedding`. Для каждой из 157 задач формируется текст (topic + title + question + golden_answer), отправляется в OpenAI `text-embedding-3-small`, вектор сохраняется в БД.

Функция запущена через curl, все 157 задач успешно получили embeddings.

### Фаза 4: Edge Function chat-assistant

**Файл:** `supabase/functions/chat-assistant/index.ts`

Основная серверная логика чата:

1. Проверка авторизации пользователя через Supabase Auth
2. Embedding вопроса пользователя через OpenAI
3. Vector search по всей базе через `match_tasks()`
4. Гарантия попадания текущего задания в контекст (даже если vector search его не нашёл)
5. Формирование system prompt с golden_answer как скрытым контекстом
6. Стриминг ответа от Groq LLM на клиент

### Фаза 5: Frontend

**Директория:** `src/features/chat-assistant/`

Создана feature по FSD-структуре:

- `api/chat.ts` — fetch к edge function с поддержкой стриминга и mock mode
- `hooks/use-chat.ts` — управление состоянием чата (messages, streaming, open/close)
- `ui/chat-button.tsx` — круглая кнопка в правом нижнем углу
- `ui/chat-panel.tsx` — боковая панель 400px с анимацией (framer-motion)
- `ui/chat-message.tsx` — пузыри сообщений с markdown-рендерингом
- `ui/chat-input.tsx` — поле ввода с авторесайзом

Чат интегрирован на страницу задания (`src/pages/task/index.tsx`).

## Code Review и исправления

После завершения разработки был проведён code review с помощью модели Claude Code Opus 4.6, выявивший 5 проблем:

1. **TextDecoder без `{ stream: true }`** — русский текст (многобайтовый UTF-8) мог ломаться на границах чанков, вызывая кракозябры. Исправлено добавлением флага `{ stream: true }`.

2. **Reader не отменялся при ошибке** — при обрыве сети ReadableStream оставался заблокированным. Исправлено добавлением `reader.cancel()` в catch-блок.

3. **Нет проверки авторизации в generate-embeddings** — любой запрос с заголовком Authorization мог запустить ре-эмбеддинг. Исправлено добавлением проверки пользователя через `auth.getUser()`.

4. **Ре-эмбеддинг всех задач при каждом запуске** — функция обрабатывала все 157 задач, даже если embeddings уже есть. Исправлено добавлением фильтра `.is('embedding', null)`.

5. **Нет лимита на размер history** — большой payload мог превысить лимит токенов модели. Исправлено добавлением бюджета `HISTORY_CHAR_BUDGET = 8000` символов (~2000 токенов).

Также обнаружена аналогичная проблема с TextDecoder в существующей функции judge (`use-task-session.ts`) — оформлена как задача для другого участника команды.

## Вынесение общего кода

В процессе разработки `corsHeaders` и `errorResponse` дублировались между edge functions. Было принято решение вынести их в общую директорию `supabase/functions/_shared/`:

- `_shared/cors.ts` — CORS-заголовки
- `_shared/error-response.ts` — формирование ответа с ошибкой

Обе новые edge functions (`chat-assistant`, `generate-embeddings`) импортируют утилиты из `_shared`.

## Итог

Реализована полная RAG-система:

- Векторный поиск по 157 задачам через pgvector + OpenAI embeddings

- Frontend чат с авторесайзом, markdown, анимацией
- Стоимость: < $1/мес на 1000 чатов
