- **Проблемы:**

При создании теста проверки установки параметра `isSubmitting` в значение true при вызове функции `resetPassword` в хуке формы регистрации столкнулся с классической проблемой тестирования асинхронных состояний в React Hook Form.

Дело в том, что `isSubmitting` в React Hook Form переключается в `true` не мгновенно, а в следующем цикле рендеринга после вызова `handleSubmit`. Когда мы проверяем его сразу после `act`, React уже успевает выполнить микрозадачу, но состояние в `result.current` может не обновиться так, как мы ожидаем в синхронном коде.

Для проверки состояние загрузки была использована утилита `waitFor` из `@testing-library/react`, но даже с `waitFor` состояние `isSubmitting` осталось `false`.

Это происходит потому, что `handleSubmit` в React Hook Form — это **высокоуровневая обертка**. Она сначала запускает валидацию Zod, и только если валидация прошла успешно, она вызывает функцию и меняет статус на `isSubmitting: true`.

- **Решение:**

Для корректной проверки переключения флага использована связка `waitFor` и вызов `form.handleSubmit(result.current.handleSubmit)`, что гарантирует прохождение цикла валидации React Hook Form перед проверкой стейта.

Вместо прямого вызова `result.current.handleSubmit`, вызвали обертку из самой формы, что гарантирует, что RHF подхватит процесс :

```react
it('should set isSubmitting to true while calling signUp', async () => {
  const { result } = renderHook(() => useRegisterForm());

  // Мокаем бесконечный промис
  vi.mocked(signUp).mockReturnValueOnce(new Promise(() => {}));

  // Запускаем сабмит через обертку handleSubmit, которую предоставляет хук
  // Важно: данные должны строго соответствоватьZod схеме!
  act(() => {
    result.current.form.handleSubmit(result.current.handleSubmit)();
  });

  // Ждем изменения состояния
  await waitFor(() => {
    expect(result.current.isSubmitting).toBe(true);
  }, { timeout: 2000 }); // Даем чуть больше времени на валидацию
});
```

Лишь такой код позволил избежать падения тестов
