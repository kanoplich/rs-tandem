# Дата: 2026-03-13

- **Что было сделано:**

Реализован функционал интеграции формы регистрации (отправка данных) на бэкенд API, для чего был создан пользовательский хук и в него была вынесена часть кода из формы регистрации, отвечающая за логику валидации, в результате чего получилось разделение: логики (хуки), представления (UI-компоненты) и данных (Zod-схемы), что сделало код более чистым и масштабируемым.

Добавлено состояние `error` и блок `try/catch`. Валидация Zod ловит ошибки "внутри" клиента (неверный формат email), а этот блок ловит ошибки "снаружи" (пользователь уже существует, сервер упал).

Задействован метод бекенда `signUp` для передачи данных формы в Supabase

- **Проблемы:**

Столкнулся с тем что не стоит лишние поля ( `confirmPassword`) передавать на сервер , к тому же для наименования поля с именем в форме используется `firstName`, а API ждет `first_name`.

- **Решение:**

Для переименования поля "на лету" и отсечения ненужного бекенду поля `confirmPassword` была задействована деструктуризация. Оказалось, что это стандартная практика: очищать или трансформировать данные перед отправкой на сервер. Правда потом по инициативе бекенда поле имени было преименовано просто в `name` и на стороне бекенда и на стороне фронта.
